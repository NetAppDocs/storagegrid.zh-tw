= StorageGRID新增網站的指南
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
您可以新增一個網站來擴充StorageGRID 您的功能。



[[guidelines-for-adding-a-site]]
== 新增站台的準則

在新增站台之前、請先檢閱下列需求與限制：

* 每個擴充作業只能新增一個站台。
* 您無法將網格節點新增至現有站台、做為相同擴充的一部分。
* 所有站台必須至少包含三個儲存節點。這些節點可以是組合式儲存節點和僅中繼資料儲存節點的任意組合。如果儲存節點超過三個，則可以是組合式儲存節點、僅中繼資料儲存節點和僅資料儲存節點的任意組合，前提是必須有三個 ADC 服務可用。如需更多資訊，請參閱 link:../primer/what-storage-node-is.html#required-storage-nodes-per-grid-and-per-site["每個網格和每個站點所需的儲存節點"]。
* 新增網站時，可儲存的物件數量不會自動增加。網格的總物件容量取決於可用儲存設備空間、ILM 原則以及每個站點的中繼資料容量。
* 調整新網站規模時、您必須確保其中包含足夠的中繼資料容量。
+
StorageGRID 會在每個站台保留所有物件中繼資料的複本。新增站台時，請確保其包含足夠的中繼資料容量，以因應現有物件中繼資料的需求，以及未來成長所需的容量。

+
如需更多資訊，請參閱下列內容：

+
** link:../admin/managing-object-metadata-storage.html["管理物件中繼資料儲存"]
** link:../monitor/monitoring-storage-capacity.html#monitor-object-metadata-capacity-for-each-storage-node["監控每個儲存節點的物件中繼資料容量"]


* 您必須考量站台之間的可用網路頻寬、以及網路延遲的層級。即使所有物件只儲存在擷取的站台、也會在站台之間持續複寫中繼資料更新。
+
為了避免因延遲而導致的效能下降：

+
** 對於延遲大於 100 毫秒的站台之間，不建議使用銷除編碼。
** StorageGRID 系統中的站點不應跨越過大的地理距離，例如跨越多個大洲。


* 由於StorageGRID 您的非功能性系統在擴充期間仍可運作、因此您必須先檢閱ILM規則、再開始擴充程序。在擴充程序完成之前、您必須確保物件複本不會儲存至新站台。
+
例如，在開始擴充之前，請檢查是否有任何規則使用了預設儲存資源池（所有儲存節點）。如果有，請使用現有儲存節點建立一個新的儲存資源池，並更新您的 ILM 規則以使用新的儲存資源池。否則，一旦該站台的第一個節點啟動，物件就會立即複製到新站台。

+
有關在新增網站時變更 ILM 原則的詳細資訊，請參閱link:../ilm/example-6-changing-ilm-policy.html["變更 ILM 原則的範例"]。
