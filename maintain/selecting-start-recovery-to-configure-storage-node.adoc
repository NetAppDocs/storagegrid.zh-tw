= 選擇 Start Recovery 以配置 StorageGRID Storage Node
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
更換儲存節點之後、您必須在Grid Manager中選取「Start Recovery」（開始還原）、將新節點設定為故障節點的替換節點。

.開始之前
* 您已使用登入 Grid Manager link:../admin/web-browser-requirements.html["支援的網頁瀏覽器"]。
* 您有link:../admin/admin-group-permissions.html["維護或根存取權限"]。
* 您有資源配置通關密碼。
* 您已部署並設定替換節點。
* 您擁有任何修復工作的開始日期、可用於銷毀編碼資料。


.關於這項工作
如果儲存節點是以容器形式安裝在Linux主機上、則只有在下列其中一項為真時、才必須執行此步驟：

* 您必須使用 `--force`旗標來匯入節點、或是您已核發 `storagegrid node force-recovery _node-name_`
* 您必須重新安裝完整節點、或是需要還原/var/local。


.步驟
. 登入主要管理節點。如果主要管理節點無法使用，請使用非主要管理節點（如果存在）。
. 從 Grid Manager 中，選擇 *Maintenance* > *Tasks* > *Node recovery*。
. 在「Pending Node」（擱置節點）清單中選取您要恢復的網格節點。
+
節點在故障後會出現在清單中、但您無法選取節點、直到節點重新安裝並準備好恢復為止。

. 請輸入*佈建密碼*。
. 點選 *Start recovery*。
. 選取 *Maintenance* > *Tasks* > *Node recovery* 並檢視恢復進度，以監控恢復進度。
+
** 如果網格節點達到「等待手動步驟」階段，您必須 link:../maintain/remounting-and-reformatting-storage-volumes-manual-steps.html["手動重新掛載並重新格式化儲存設備磁碟區"]。完成手動步驟後，請繼續 link:../maintain/restoring-object-data-to-storage-volume.html["將物件資料還原到磁碟區中"]。
** 如果網格節點恢復已從「進行中」狀態轉換至「已恢復」狀態，而未經過「等待手動步驟」階段，則無需採取進一步行動。
+
[NOTE]
====
在恢復過程中的任何階段，您都可以選擇 *Reset* 來開始新的恢復。此時會出現一個對話方塊，提示如果您重設程序，節點將處於不確定狀態。

如果您想在重置程式後重試恢復，則必須將應用裝置節點還原到預安裝狀態，如下所示：

*** * VMware*：刪除已部署的虛擬網格節點。然後、當您準備好重新啟動恢復時、請重新部署節點。
*** *Linux* ：在 Linux 主機上執行以下命令、重新啟動節點： `storagegrid node force-recovery _node-name_`


====
